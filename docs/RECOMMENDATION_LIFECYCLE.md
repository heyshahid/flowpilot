# FlowPilot — Recommendation Lifecycle State Machine (Phase 9G)

## 1. Lifecycle State Machine

Recommendations progress through explicit lifecycle states managed by authorized workspace users:

```
           ┌──────────┐
           │   NEW    │◄─────────────────────────┐
           └────┬─────┘                          │
                │ (User views / clicks)          │
                ▼                                │
           ┌──────────┐                          │
      ┌───►│  VIEWED  │                          │
      │    └────┬─────┘                          │
      │         │                                │
      │  ┌──────┴────────────────┐               │
      │  │                       │               │
      │  ▼                       ▼               │
┌───────────┐              ┌───────────┐         │ (Regeneration on
│  SNOOZED  │              │ DISMISSED │         │  new evidence after
└───┬───────┘              └───────────┘         │  resolve/dismiss)
    │ (Auto-expires)             │               │
    └────────────────────────────┼───────────────┘
                                 │
                                 ▼
                           ┌───────────┐
                           │ RESOLVED  │
                           └───────────┘
```

### State Definitions
- `NEW`: Newly generated by an evaluation run. Has not been reviewed by a team member.
- `VIEWED`: Opened or inspected by a user in the UI.
- `SNOOZED`: Temporarily hidden until `snoozedUntil` timestamp expires (e.g. 1 day, 7 days, 30 days). Once expired, it returns to `VIEWED` status.
- `DISMISSED`: Dismissed by a user with a mandatory reason (e.g. `ACCEPTED_RISK`, `INTENDED_BEHAVIOR`, `NOT_APPLICABLE`).
- `RESOLVED`: Remediation completed by user with resolution notes.

---

## 2. Deduplication & In-Place Updates

When an evaluation run executes:
1. A deterministic `dedupKey` is generated:
   $$\text{dedupKey} = \text{rec\_}\{workspaceId\}\_\{ruleId\}\_\{targetId\}$$
2. If an active recommendation exists with status `NEW`, `VIEWED`, or `SNOOZED`:
   - It is **updated in-place** rather than duplicated.
   - `lastEvaluatedAt` is refreshed to the current timestamp.
   - `occurrenceCount` increments by 1.
   - New evidence, priority, and confidence scores are refreshed.

---

## 3. Regeneration Safeguards

A critical requirement is that resolving or dismissing an issue must **not** permanently suppress recommendations if the underlying issue recurs after remediation:

1. **Suppression on Stale Telemetry**:
   - If an evaluation occurs with evidence whose `measurementPeriod.to` is **prior to or equal to** the dismissal or resolution date, the recommendation remains suppressed.
2. **Regeneration on Fresh Evidence**:
   - If new qualifying evidence occurs with a timestamp **strictly newer than** the dismissal or resolution date, the system generates a **new recommendation** with status `NEW`.
   - The prior record and its history remain untouched in `.data/recommendation_history.json`.

---

## 4. Immutable History Audit Trail

Every lifecycle action produces an immutable record in `.data/recommendation_history.json`:
- `id`: Unique history entry ID (`hist_...`).
- `recommendationId`: Associated recommendation identifier.
- `fromStatus` & `toStatus`: State change transition.
- `performedBy` & `performedByName`: Actor identity.
- `notes`: Justification or resolution notes.
- `timestamp`: ISO 8601 audit timestamp.
