### 1. Executive Summary & Purpose

Phase 9G builds the intelligence layer of FlowPilot by synthesizing operational telemetry collected across Phases 9A through 9F into practical, evidence-backed, advisory-only optimization recommendations.

The primary objective is to transform raw analytics (latencies, failure trends, timeout counts, token distributions, webhook deliveries, scheduling anomalies, and quota thresholds) into structured, actionable insights. Every recommendation explains:
1. **What** problem or opportunity was identified.
2. **Where** it occurred (specific workflow, node, integration, schedule, or workspace).
3. **Why** it matters.
4. **What evidence** supports the finding (with exact metrics, samples, and time windows).
5. **How** the user can address it.
6. **Estimated Impact** (conservative, explicitly marked as estimated).
7. **Confidence Level** (statistically grounded, lowered on small samples).
8. **Known Limitations & Missing Data** (honest disclosure).

In adherence to strict platform governance: **Phase 9G is strictly advisory-only. The system will never silently alter, reconfigure, pause, or delete user workflows.**

### 3. Data Completeness Disclosures & Data Gaps

Every recommendation generated by Phase 9G includes a mandatory `dataLimitations` disclosure array to avoid misleading assertions:

1. **Bounded Execution Retrieval**: Execution queries are bounded at 500 records per evaluation to preserve performance. Findings reflect this bounded observation sample.
2. **Rolling Webhook Buffer**: Webhook deliveries are limited by the platform's 500-record rolling storage buffer (`WebhookStore`).
3. **Unpriced AI Models**: Invocations using models absent from the versioned catalog (`AIPricingManager`) are disclosed as unpriced rather than misleadingly priced at $0.00.
4. **Single-Instance Execution**: Worker queues and cron schedulers operate as single-process in-memory components; queue bottlenecks reflect single-node execution constraints.
5. **No Synthetic Benchmarks**: Thresholds (e.g. 30s p95, 50k tokens, 40% node contribution) are **initial diagnostic heuristics**, not universal definitions of poor performance.

### 4. Complete Recommendation Category Matrix (8 Concrete Categories)

Phase 9G implements 8 distinct categories, each with concrete diagnostic rules, detection logic, and evidence contracts:

#### 1. Workflow Performance Optimization (`WORKFLOW_PERFORMANCE`)
* `PERF_SLOW_WORKFLOW_P95`: P95 duration $> 30,000\text{ms}$ with $\ge 5$ terminal runs.
* `PERF_DURATION_DRIFT`: Recent 5-run average duration $> 50\%$ higher than historical baseline.
* `PERF_POTENTIAL_PARALLELIZATION`: Sequential independent HTTP/AI nodes detected where execution order could safely be parallelized.

#### 2. Node-Level Optimization (`NODE_OPTIMIZATION`)
* `NODE_DISPROPORTIONATE_DURATION`: Single node consumes $\ge 40\%$ of overall workflow mean duration ($N \ge 5$).
* `NODE_EXCESSIVE_RETRIES`: Node exhibits average retry count $\ge 1.5$ per run or $> 30\%$ retry rate across traces.
* `NODE_FREQUENT_TIMEOUTS`: Node triggers timeout errors (ETIMEDOUT, 504, regex) in $> 15\%$ of attempts.

#### 3. Workflow Reliability (`RELIABILITY`)
* `REL_LOW_SUCCESS_RATE`: Overall terminal success rate $< 80\%$ with $\ge 5$ completed/failed executions.
* `REL_REPEATED_STAGE_FAILURE`: $\ge 3$ consecutive workflow runs fail at the exact same step/node.

#### 4. Integration Optimization (`INTEGRATION`)
* `INT_WEBHOOK_REJECTION_SPIKE`: Webhook rejection/failure rate $\ge 15\%$ over active window.
* `INT_RATE_LIMIT_BACKOFF`: Outbound integration traces surface HTTP 429 / Rate Limit responses ($\ge 3$ occurrences).
* `INT_AUTHENTICATION_EXPIRED`: Credential failures (HTTP 401/403) detected on configured integration credentials.

#### 5. AI Usage & Cost Optimization (`AI_COST`)
* `AI_HIGH_TOKEN_CONSUMPTION`: Workflow consumes $> 50,000$ tokens per run or $> 200,000$ tokens monthly.
* `AI_MODEL_TIERING_OPPORTUNITY`: Heavy general-purpose reasoning models (e.g. GPT-4 / Claude Opus) used for basic string extraction or simple formatting where lightweight models (Flash / Mini) are more economical.
* `AI_UNPRICED_MODEL_USAGE`: Substantial usage of custom/unmapped models lacking verified catalog pricing.

#### 6. Scheduling Optimization (`SCHEDULING`)
* `SCHED_MISSED_RUNS`: Active schedules overdue by $> 5$ minutes without recorded execution.
* `SCHED_INTERVAL_CONGESTION`: Multiple schedules triggering at the exact same cron boundary (e.g. top of the hour `0 * * * *`) causing execution queue spikes.

#### 7. Workspace Resource Optimization (`RESOURCE_USAGE`)
* `RES_LIMIT_APPROACHING`: Resource metric (workflows, executions, schedules, AI cost) exceeds 80% (`WARNING` state) of configured quota.
* `RES_LIMIT_EXCEEDED`: Resource metric exceeds 100% (`LIMIT_REACHED` state).

#### 8. Workflow Architecture & Graph Topology (`WORKFLOW_ARCHITECTURE`)
* `ARCH_UNHANDLED_ERROR_PATH`: Critical action/HTTP/AI nodes lacking configured error fallback branches or retry configurations. Detection: Inspects `WorkflowRecord.nodes` and `edges` for failure exit ports (`onError` / `false` branch).
* `ARCH_HIGH_FANOUT_WITHOUT_BATCHING`: Workflow graph with excessive parallel fan-out ($> 10$ branching nodes) from a single trigger without batching or rate throttling.
* `ARCH_UNBOUNDED_LOOP_RISK`: While-loop or loop-iterator nodes without configured maximum iteration limits.

### 5. Deterministic Priority & Confidence Scoring Methodology

Priority and Confidence are decoupled into deterministic, independently testable algorithms.

#### A. Deterministic Priority Score ($P \in [10, 100]$)
$$P = S_{\text{severity}} + F_{\text{frequency}} + I_{\text{impact}}$$

1. **Severity Component ($S_{\text{severity}} \in [10, 40]$)**:
   * `CRITICAL`: 40 points
   * `HIGH`: 30 points
   * `MEDIUM`: 20 points
   * `LOW`: 10 points
2. **Frequency Component ($F_{\text{frequency}} \in [0, 30]$)**:
   * Calculated from the normalized ratio of affected executions or occurrences:
     $$F_{\text{frequency}} = \min\left(30, \; \text{round}\left(\frac{\text{affectedExecutions}}{\text{totalExecutions}} \times 30\right)\right)$$
   * For non-execution rules (e.g. quota, schedule congestion), calculated from occurrence count normalized to $[0, 30]$.
3. **Impact Component ($I_{\text{impact}} \in [0, 30]$)**:
   * Calculated from the magnitude of the condition (e.g. latency ratio, token scale, quota proximity):
     $$I_{\text{impact}} = \min\left(30, \; \text{round}\left(\text{impactRatio} \times 30\right)\right)$$
   * Example: A 90% quota usage yields $\text{round}(0.90 \times 30) = 27$ impact points.

#### B. Deterministic Confidence Score ($C \in [25, 100]$)
$$C = S_{\text{sample}} + Q_{\text{completeness}} + C_{\text{consistency}}$$

1. **Sample Size Factor ($S_{\text{sample}} \in [15, 50]$)**:
   * $N < 3$: 15 points (severe low-sample penalty)
   * $3 \le N < 5$: 25 points
   * $5 \le N < 10$: 40 points
   * $N \ge 10$: 50 points (full statistical basis)
2. **Data Completeness & Quality ($Q_{\text{completeness}} \in [10, 30]$)**:
   * Baseline: 30 points.
   * Deduct 10 points if unpriced AI requests exist in the sample.
   * Deduct 10 points if webhook deliveries hit the 500-buffer cap.
   * Deduct 10 points if $> 20\%$ of executions in window were cancelled.
   * Floor: 10 points.
3. **Consistency Factor ($C_{\text{consistency}} \in [0, 20]$)**:
   * 20 points: Observed across multiple independent workflow execution runs or multiple days.
   * 10 points: Observed across a single execution or narrow time window.
   * 0 points: Isolated single-event observation.
4. **Confidence Categorization**:
   * $C \ge 80 \implies \text{HIGH}$
   * $50 \le C < 80 \implies \text{MEDIUM}$
   * $C < 50 \implies \text{LOW}$
   * *Mandatory Note*: Confidence score is an empirical index of data completeness and measurement consistency, **never a statistical probability of outcome**.

### 6. Deduplication, Lifecycle & Regeneration Safeguards

```
[ Evaluation Triggered ]
         |
         v
[ Find Existing Active Recommendation ]
(matches workspaceId + ruleId + targetId AND status IN ['NEW', 'VIEWED', 'SNOOZED'])
      /                                 \
   Found                                Not Found
   /                                       \
[ Active Recommendation Exists ]        [ Check Historical Records ]
- Update occurrenceCount (+1)           (matches status IN ['DISMISSED', 'RESOLVED'])
- Update lastSeenAt (now)                      /                      \
- Update latest evidence metrics             Found                  Not Found
- If SNOOZED and duration expired:             /                        \
    Revert status to NEW                 [ Has Condition Changed? ]   [ Create NEW Record ]
                                         - New window timestamp?      - Status: NEW
                                         - Significant metric delta?  - Fresh Lifecycle
                                                /           \
                                              Yes            No
                                              /               \
                                    [ Create NEW Record ]   [ Suppress Regeneration ]
                                    (Preserve old record    (Honor user dismissal)
                                     in audit history)
```

1. **Active Deduplication**: If an active recommendation (`NEW`, `VIEWED`, `SNOOZED`) already exists for the same `workspaceId + ruleId + targetId`, it is updated in-place (occurrence counter incremented, latest measurements updated), preventing duplicate active cards.
2. **Snooze Expiration**: If `snoozedUntil` has passed, the recommendation automatically reverts to `NEW` on the next evaluation run.
3. **Regeneration on New Evidence**: If a recommendation was previously `RESOLVED` or `DISMISSED`, a new recommendation is only generated if:
   * The current evaluation window timestamp is strictly newer than the resolution/dismissal date, **AND**
   * A genuinely new qualifying incident occurs (e.g. failure rate re-escalates or new consecutive errors appear). The historical record remains archived in the history log.
4. **Concurrent Evaluation Protection**: In-memory evaluation locks per workspace prevent overlapping evaluation runs from creating race conditions.

### 7. User Interface & Empty-State Specifications (`/recommendations`)

* **Strict Neutral Empty State**: When no recommendations are generated, the UI displays:
  > **"No optimization recommendations have been identified from the available data."**  
  > (No misleading claims about "optimal performance").
* **Advisory Disclaimer**: Prominently displays:
  > *"FlowPilot recommendations are advisory analyses intended to highlight potential optimization opportunities. FlowPilot never alters, disables, or modifies workflows automatically."*
* **Detailed Cards & Modal**:
  * Shows Category, Severity, Priority Score ($0-100$), Confidence Tier (`HIGH`/`MEDIUM`/`LOW`), Affected Target, Summary, Exact Supporting Measurements, Suggested Next Steps, and Data Limitations.
  * Direct deep links to builder `/builder/[id]`, analytics `/analytics/workflows/[id]`, or credentials `/credentials`.
  * User feedback buttons (`Helpful`, `Not Helpful`, `Already Fixed`, `Not Relevant`, `Incorrect`).
