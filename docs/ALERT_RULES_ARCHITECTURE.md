# FlowPilot Configurable Alert Rules Architecture

**Milestone:** Phase 9F — Module 9F-C  
**Target:** User-Configurable Threshold Rules, Evaluation Engine & Cooldown Safeguards  
**Route:** `/alerts`  
**Endpoints:** `/api/v1/alerts/rules`, `/api/v1/alerts/rules/[id]`, `/api/v1/alerts/rules/evaluate`  

---

### 1. Alert Rule Data Model

Each alert rule represents a persistent declarative condition evaluated against actual platform metrics:

```typescript
interface AlertRule {
  id: string;
  workspaceId: string;
  name: string;
  description?: string;
  category: AlertCategory;
  metric: AlertMetric;
  operator: AlertOperator;
  threshold: number;
  evaluationWindowMinutes: number;
  cooldownMinutes: number;
  severity: AlertSeverity;
  enabled: boolean;
  targetWorkflowId?: string;
  channels: NotificationChannel[];
  createdAt: string;
  updatedAt: string;
  createdBy: string;
  lastEvaluatedAt?: string;
  lastTriggeredAt?: string;
}
```

---

### 2. Supported Categories & Metrics

#### 1. Execution
* `failure_rate`: Terminal failure percentage over the evaluation window ($\ge$ threshold %).
* `consecutive_failures`: Number of consecutive workflow failures.
* `execution_duration_p95`: 95th percentile execution latency in milliseconds.
* `stuck_executions`: Number of executions in `RUNNING` or `QUEUED` state for > 15 minutes.

#### 2. Scheduling
* `missed_schedules`: Number of active schedules whose target execution time is past due by > 5 minutes without a recent run.
* `schedule_failure_rate`: Failure percentage of scheduled workflow executions.

#### 3. Integration
* `integration_failure_rate`: Failure rate across all outbound third-party adapter executions.
* `webhook_error_rate`: Percentage of inbound webhooks rejected or failed.

#### 4. AI Usage
* `monthly_cost_usd`: Aggregate estimated AI expenditure in the rolling 30-day window.
* `monthly_tokens`: Total AI tokens consumed in the rolling 30-day window.
* `unpriced_requests_count`: Invocations missing official provider pricing rates.

#### 5. Workspace Usage
* `workflow_limit_pct`: Total workflows as a percentage of configured quota.
* `execution_limit_pct`: Current executions as a percentage of monthly quota.
* `schedule_limit_pct`: Active schedules as a percentage of quota.
* `ai_cost_limit_pct`: Monthly AI cost as a percentage of cost ceiling.

### 3. Rule Evaluation & Cooldown Safeguards

```
[ Rule Engine Triggered ]
         |
         v
[ Fetch Rule & Window Data ]
         |
         v
[ Calculate Metric Value ]
         |
         v
[ Operator Comparison: (value OP threshold)? ]
      /      \
    No        Yes
   /            \
[ Return Ok ]   [ Check Cooldown Window ]
                (now - lastTriggeredAt < cooldownMinutes?)
                    /      \
                  Yes       No
                 /            \
    [ Skip Trigger / Log ]   [ Trigger Incident ]
                             [ Update lastTriggeredAt ]
                             [ Dispatch Notifications ]
```

* **Deterministic Deduplication**: Incidents generated by a rule use deterministic keys:
  $$\text{dedupKey} = \text{inc\_} + \text{workspaceId} + \text{\_} + \text{ruleId} + \text{\_} + (\text{targetWorkflowId} \lor \text{"global"})$$
* **Cooldown Protection**: Once triggered, a rule will not spawn new incident notifications until the `cooldownMinutes` duration expires, eliminating alert fatigue.
